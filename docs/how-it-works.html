Kuthay P2P — How It Works

Connecting two smartphones 3–4 km apart directly over Indian cellular networks using IPv6 hole-punching. Every concept, protocol and design decision used in the prototype, explained with diagrams.

1 · The problem — and why radio can't solve it

Two phones stand 3–4 kilometres apart. No radio inside a smartphone reaches even a tenth of that.

Fig 1 — Effective range of phone radios vs the required 3–4 km gap

  • Wi-Fi Direct / Aware / BLE — designed for same-room links. Even a chain of relaying phones would need dozens of cooperating strangers.
  • Cellular sidelink (PC5) — the one true cellular D2D standard (3GPP Rel-12+). Real in V2X chips, but exposed by zero consumer operators: no API on Android/iOS, resource pools controlled by the tower.
  • The realistic path — both phones already hold an internet connection through their SIMs. We build a logical peer-to-peer channel across the operator network and make it as direct as the infrastructure allows.

2 · The obstacle course — NAT and carrier-grade NAT

A direct connection means packets flowing straight from one phone to another. The internet's addressing was never designed to allow that.

IPv4 has only ~4.3 billion addresses and mobile networks have far more devices than that, so carriers put thousands of subscribers behind each public IP using carrier-grade NAT (CGNAT). Every phone gets a private address (10.x.x.x) and every outbound packet is rewritten:

Fig 2 — Left: many devices squeezed through one public IPv4. Right: IPv6 gives every handset its own identity.

Symmetric NAT — why probes lie to you

To connect two peers you must learn each one's public endpoint. The classic tool is a STUN server: “send me a packet, I'll tell you what I saw.” Behind symmetric CGNAT that answer is a trap:

3 · Why IPv6 changes everything — especially in India

India accidentally became the perfect laboratory for direct P2P: mobile operators skipped IPv4 expansion and went straight to IPv6.

With IPv6 there is no address shortage, so there is no NAT device rewriting your traffic. Each phone holds a globally unique address handed out via SLAAC when the radio attaches to the network. Two phones 4 km apart already possess everything needed to address each other directly.

One gatekeeper remains: carriers still run stateful firewalls that drop packets arriving from outside unless the phone recently sent something outward. That is not a translation problem — it's a door that only opens from the inside. Which brings us to punching.

4 · UDP hole-punching — opening doors from the inside

Both peers knock outward at each other simultaneously. Each knock creates firewall state; the opposite side's knock slips in through it.

Fig 3 — Simultaneous-open punch. Neither side needs inbound rules; both create their own.

  • Timing window — firewall state lives tens of seconds; our prototype re-sends every 350 ms for up to 60 s, so overlap is guaranteed.
  • Keepalive — after connecting we slow to one packet per 2 s so the doors never close.
  • UDP preferred — connectionless, cheap for firewalls to allow, ideal for punch mechanics. TCP simultaneous-open exists but midboxes mishandle it more often.
  • RTT for free — each PING embeds the sender's clock reading; the echoed PONG returns it, so the pinger measures round-trip time with its own clock.

One tiny public server introduces the peers. Everything heavy happens phone-to-phone afterwards.

Deliberately boring JSON and pipe-delimited strings. Debuggable with eyes alone.

9 · Glossary

NAT
— Network Address Translation: rewrites IP/port pairs so many devices share few public addresses; breaks unsolicited inbound traffic.
CGNAT
— Carrier-grade NAT at ISP scale; uses the reserved 100.64.0.0/10 pool internally (RFC 6598).
Symmetric NAT
— The hostile kind: external port differs per destination, so endpoints learned from a STUN server are worthless to peers.
STUN
— Session Traversal Utilities for NAT: a server reflects your packet back annotated with the source address it saw.
TURN
— Traversal Using Relays around NAT: routes media through a server when direct paths die. Costs bandwidth; avoided here whenever possible.
ICE / srflx
— ICE gathers candidates (host / server-reflexive / relay) and tests pairs; “srflx” is the address a STUN-like server reports seeing.
Hole punching
— Simultaneous outbound sends creating reciprocal firewall state, letting two previously unreachable peers exchange packets directly.
Stateful firewall
— Allows return traffic only for flows it saw leave first — the one remaining gatekeeper on native IPv6.
SLAAC
— IPv6 Stateless Address Autoconfiguration: phones derive global addresses from router advertisements when attaching to the network.
Privacy extensions
— Rotating temporary IPv6 addresses against tracking; irrelevant mid-session since the app pins one socket.
Half-open
— One-way reachability: peer→you arrives, you→peer is filtered. Signature of asymmetric middlebox policy.
RTT
— Round-trip time, measured by echoing the pinger's own timestamp back so clocks never need syncing.
Sidelink / ProSe (PC5)
— 3GPP device-to-device radio interface. Standardised, real in V2X chips, absent from consumer networks — hence this detour through IP.
NTN D2D
— Non-Terrestrial Network direct-to-device (BSNL×Viasat in India): satellite messaging where towers end. Messaging-grade only.
Foreground service
— Android's mechanism for long-running user-visible work; keeps our sockets alive past screen-off.
